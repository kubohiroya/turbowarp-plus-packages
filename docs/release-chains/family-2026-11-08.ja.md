# family の依存更新（2026-11-08）

[#96](https://github.com/kubohiroya/turbowarp-plus-packages/issues/96) の手順 3 として、family の古い依存を 1 回の連鎖でまとめて更新します。

## 起点

2026-11-08 の collect（`2026-11-08T13:21:52.571Z`、snapshot `b98bf788…`）で、古い family 依存を抱えた依存元がいる起点は次の 5 つでした。

| 起点 | 古い依存の辺 |
|---|---|
| vite-plugin-turbowarp-extension | 30 |
| turbowarp-extension-data-editor | 25 |
| sb3-toolchain | 8 |
| turbowarp-extension-loader | 3 |
| turbowarp-document-source | 1 |

起点ごとに計画すると、共通の依存元を起点の数だけ公開し直すことになります。たとえば kamishibai-app は 5 回、plus-editor は 4 回です。
そこで 5 つを 1 つの計画にまとめました（#97）。

```sh
npm run --silent bump:downstream -- vite-plugin-turbowarp-extension turbowarp-extension-data-editor \
  sb3-toolchain turbowarp-extension-loader turbowarp-document-source --reconcile --json > plan.json
npm run --silent release -- --plan plan.json --workspace <ws> --discover --repos-dir <repos> \
  --config docs/release-chains/family-2026-11-08.exceptions.json > preview.json
npm run release -- --plan plan.json --workspace <ws> --resolved preview.json \
  --execute --confirm <digest> --concurrency 4
```

## 例外とレビュー

例外の指定は [`family-2026-11-08.exceptions.json`](family-2026-11-08.exceptions.json) です。
install・検証・公開の手順は 60 repo すべてで既存の package.json と `release.yml` から解決できました。
手順の上書き（`repositories`）は、実行の途中で見つかった次の 1 件だけです。

- **camera-calibration の prepare：** `THIRD_PARTY_NOTICES.md` は、同梱する依存（camera-source、data-editor）の版を「exact npm version `0.22.0`」のように本文に書き、`check-repo` が package.json と照合します。
  依存を上げると本文も直す必要があるので、既定の準備（`docs` → `build` → `samples:build`）の前に、入力 SHA の package.json から変わった依存の版を `` `旧版` `` → `` `新版` `` に置き換えます。
  旧版の表記が本文にちょうど 1 か所ないときは、推測せずに止まります。

レビューが必要な対象は次の 10 repo です。

- **peer の互換性：** binary-data、structured-data、http-server、realtime-motion-capture、webrtc-qrcode-pairing
- **RC 系列の継続：** document-editor、named-functions、structured-data、sb3-save-format、kamishibai-app、plus-editor
- **Git 依存から npm 版への置き換え：** plus-editor。document-editor の Git 参照 `4039927` を npm の 0.1.0-rc.8 に置き換えます。

`reviewedRepositories` には、実行の前にユーザーが承認した repo だけを残します。
